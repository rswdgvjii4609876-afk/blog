# 公众号随笔迁移

本文集由用户提供正文并确认可全文迁移。保留原文措辞（包括原有个别错字）、日期和引用；仅调整 Markdown 段落、引用及“写在最后”标题。标题、首页摘要和原文链接见 `manifest.json`。来源链接按用户提供的六篇顺序对应；微信网络访问受限，未独立核对链接内的标题与发布日期。未附加作者姓名或虚构图片。

## 导入线上网站

在服务器项目目录运行，无需重新构建镜像，也不直接改数据库。通过现有管理接口登录，遵守 CSRF 校验和修订记录规则。

```bash
cd /opt/zhixing/blog
git pull --ff-only
python3 scripts/import-essays.py --url https://43.132.227.52
# 上一步仅预览。输入自己设置的 admin 密码，不会回显或保存。
python3 scripts/import-essays.py --url https://43.132.227.52 --apply
```

默认只将“你好，世界”“Spring Boot 起步笔记”“为什么用 Thymeleaf”三篇示例转为草稿，不删除内容、评论或修订。其他测试文章（例如标题“5”）必须先在后台确认 ID，再显式加 `--archive-id 文章ID`，可重复指定。不要根据数字标题自动识别垃圾文章。

写入前将全部旧文章的标题、摘要、正文、状态及版本备份到 `backups/essays-时间/articles.json`（不含账号密码、Cookie 或 CSRF token）；目录权限700，文件600，已被 Git 忽略。这是文章内容备份，不包含评论、评分、投票等完整数据库；完整网站备份仍应采用 DEPLOYMENT.md 的停应用复制数据卷流程。

按所提供的文章顺序发布，因此“砒霜与蜜糖、美味与毒药”排在首页最前。站内日期为实际导入时间，正文保留原有写作日期；未提供的日期不推测。同名且正文完全相同的文章会跳过；同名内容不同则停止，避免覆盖编辑后的作品。不要在导入过程中同时编辑文章。

网络中断可能造成部分文章已发布：再次执行会跳过成功项并继续；所有新文章发布成功后才将示例转为草稿。操作不是跨多个请求的数据库事务。若需撤回，在后台将新文章设为草稿，再把旧文章恢复为已发布；备份正文也可复制回编辑器保存并留下修订。

迁移不会随着应用启动自动执行；Git 拉取或重新部署不会擅自替换生产数据库。

## 本轮验证

使用当前可执行 JAR 和两套独立内存数据库验证：本机开发模式成功导入六篇文章、示例转草稿；六个公开详情页包含来源链接，引用正确渲染；重复执行无新增。另开启真实管理员认证，使用临时随机密码验证登录、CSRF、只读预览、首次写入及重复运行。备份中不保存密码或会话。未更改 Java 应用或数据库结构，因此本轮未重跑完整 JVM 测试；未连接生产数据库执行迁移。

## 提交前在服务器验收

完成导入后执行 `bash scripts/pre-submit-check.sh`。脚本短暂停止应用，复制完整 `/app/data`（包含文章、评论、评分及互动数据库），私密保存现有部署配置，然后恢复服务，检查公网健康、两页文章详情和来源、身份入口及后台登录保护。备份保存在忽略的 `backups/pre-submit-时间/`。这不包含 Caddy 证书卷；证书由 Caddy 管理，备份也仍在同一服务器。脚本有失败退出和恢复应用保护，但不能代替恢复演练、异地备份或手机电脑人工验收。本脚本尚未在用户生产服务器执行验证。
